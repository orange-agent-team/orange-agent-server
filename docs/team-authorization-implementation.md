# 团队与资源授权实施记录

日期：2026-11-04；关联 CP-002、SEC-004。实现位置是 E07 的 `team` 模块、迁移0004和E02的team DTO。当前为真实数据库内部服务切片，**尚未开放公共用户登录/团队HTTP接口**，不将测试用户记录当作已验证的用户OIDC。

## 已实现行为

- 个人身份与组织钱包分开；创建组织时生成独立零余额钱包，不能复制个人余额或创建无限预算。成员上限创建时只能在1—20之间选定，数据库硬上限100保留给未来有容量证据的运营配置。
- 五种组织角色分别处理。owner/admin管理成员；admin不能操作owner/admin或授予这些角色。创建或写内容只允许owner/admin/member；viewer只读，billing不能取得正文访问权。
- 内容ACL独立于组织角色。新资源仅给创建者显式write；owner/admin不能绕过ACL查看成员私有资源，也不能给自己补授权。修改共享要求当前写权限、当前可写角色和创建者身份；每次读/写重新检查用户、组织、成员、ACL及删除状态。
- 组织行锁序列化成员变更；CAS政策版本处理过期修改。移除或降级最后一个有效owner被拒绝，禁用用户不计作可用owner。成员额度在同一组织锁下计数。
- 成员移除在同一事务撤销其资源ACL。重新加入不会恢复历史内容授权，原创建请求也不能绕过当前权限或删除标记。
- 幂等键绑定actor、scope、操作及规范请求摘要，保留原结果。所有重放先校验当前权限；创建组织的旧结果也要求仍是该组织成员。创建键使用PostgreSQL事务级advisory lock，成员/资源修改使用组织与资源行锁，不依赖单进程内存锁。
- 修改事务写入不可变团队审计，记录业务身份与摘要，不保存原始内容或密钥。组织与资源历史归属不因成员变更而移动。

## 内部接口

| 方法 | 输入 | 结果与边界 |
|---|---|---|
| create_organization | 已认证actor、幂等键、名称/成员上限 | 固定组织ID、独立钱包、创建者owner |
| set_membership | actor、组织、幂等键、目标用户/角色或移除、政策版本 | 原子成员变化、撤权、递增政策版本、审计 |
| register_resource | actor、组织、幂等键、thread/run/artifact/memory/skill类别 | 私有元数据登记；不上传内容，不产生模型消费 |
| resource | actor、组织、资源ID、read/write | 当前授权后的元数据；不是可以缓存复用的交付凭证 |
| set_acl | actor、组织、资源、幂等键、目标授权及ACL版本 | 原子共享/撤销、ACL及政策版本、审计 |

actor必须由未来身份边界提供，不能接受请求body自行指定。内容下载、模型调用和工具执行仍须在各自提交/返回边界重新检查当前权限；本切片不会把一次元数据查询当作永久能力。组织身份停用、完整退出和内容删除流程仍需独立服务实现；直接数据库维护不是产品授权接口。

## 已运行的验证

`python3 scripts/check.py --teams` 使用专用真实PostgreSQL执行四项集成测试：

1. 五角色与显式ACL组合、私有内容拒绝、owner不能自授访问、跨组织拒绝及删除后不可恢复。
2. 两个owner并发互相移除最多一个成功、最后owner保护、撤权后旧管理请求拒绝，以及团队钱包初始为零。
3. admin不可提升自身、成员容量拒绝、共享后撤销/重新加入不恢复、同键异内容拒绝和审计不可删除。
4. 原创建者退出后不能读取创建幂等结果，重新加入也不能通过旧资源创建键恢复内容访问。

测试身份是隔离数据库夹具，没有向任何人发送邀请。未完成：用户OIDC/公共API、邀请接受、成员消费额度、组织硬预算周期、完整对象存储交付、用户停用与组织退出流程及前端。原CP-002/SEC-004父任务因此仍保持未完成。
