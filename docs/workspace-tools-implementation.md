# 工作区只读工具与授权租约

2026-11-04；当前覆盖TK-01 list_directory与TK-02 read_file，不代表24个G3工具或完整OS/进程沙箱已完成。

工作区由可信宿主在明确授权后用cap-std 4.0.3打开为目录能力；cap-fs-ext 4.0.3逐组件禁止符号链接跟随。模型只提供相对路径，不能选择ambient根、owner、授权或策略版本。环境摘要绑定owner、授权ID、策略、规范根路径和目录身份/创建信息；已知私有数据根与工作区不能互相包含。

路径拒绝绝对/父目录/UNC/设备/ADS样式、控制字符、不可移植别名和敏感目录/凭证文件名。所有中间目录及最终文件都不跟随链接，Unix多硬链接文件也拒绝。Unix使用nonblock后确认普通文件；二进制、NUL及非UTF-8内容不作为文本返回。Windows代码使用能力库的跨平台实现，但该机器上的实测不能替代Windows目标验证。

read_file支持字节偏移/上限或1基行范围，以及可选完整文件SHA-256。单文件10MiB，单次最多1MiB，原始结构化结果不超过2MiB。返回完整文件摘要、总大小、实际范围与明确truncated/next_byte；模型视图再限制到64KiB，不截断UTF-8编码。检测到读取期间长度/mtime变化或预期摘要不符即拒绝，不将其当同一版本。

list_directory仅返回可寻址的常规文件/目录元数据，过滤敏感/不支持条目。每次扫描最多10000条，页面在请求上限与输出边界内返回，当前每页最多80项；游标绑定环境、目录、可见元数据快照及最后名称。快照变化要求重新分页，不静默混合两个列表。它不是文件内容的原子快照或任意目录遍历器。

整个宿主的只读I/O默认最多4并发。`prepare`只取得权限与容量，不读取目标文件；宿主必须先持久化派发事实，再调用PreparedTool.execute。结果回执保持授权租约，直到调用者保存或丢弃结果。撤销请求立即禁止新租约，wait_drained等待旧租约释放；不能只凭取消请求就声称全部I/O已完成。执行超时/调用者取消会收紧当前grant，阻塞线程仍持有其权限租约直到结束。宿主还必须把撤权写入持久Run/授权状态，不能只依赖这个进程内标志完成恢复语义。

六项实际文件系统测试覆盖：UTF-8字节/行与摘要，路径/主体/策略拒绝，结果大小/二进制/大文件，分页与变更，符号链接/硬链接越界，以及撤权和结果发布租约排空。执行 `python3 scripts/check-workspace-tools.py`。测试只使用隔离目录，未读取用户凭证。

剩余：宿主持久控制循环、写工具/进程隔离、全面秘密分类、目标平台矩阵和云工作区生命周期。内容仍是不可信数据；工具返回不能授予权限、批准下一操作或改动预算。

接口依据：[cap-std目录能力](https://docs.rs/cap-std/4.0.3/cap_std/fs/struct.Dir.html)、[不跟随目录链接](https://docs.rs/cap-fs-ext/latest/cap_fs_ext/trait.DirExt.html)、[文件打开控制](https://docs.rs/cap-fs-ext/latest/cap_fs_ext/struct.OpenOptions.html)。
