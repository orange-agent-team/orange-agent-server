# 多条记忆来源的持久边界（schema26基础切片）

此切片为后续发现/列表工具准备真实的有界多条目引用存储，同时加固当前 v1 工具的结果完整性。它没有向模型暴露发现工具，也没有改变 memory_read.v1/memory_write.v1 的固定参数、序列化或执行 pin。

## 迁移和约束

schema26 在一个 SQLite IMMEDIATE 事务内把 runtime_memory_sources 的单列 operation_id 主键改为 (operation_id, scope_id, entry_id)。逐行复制已有 operation/scope/entry/version，不改变旧上下文、回执、批准或来源图。每个操作最多 100 条引用，引用必须属于 runtime_memory_operations 已绑定 scope；条目 FK、正版本、禁止更新和禁止删除约束保留。同一条目一次结果只能记录一个版本。

升级后 schema25 及更旧程序必须在变更数据库前拒绝打开。source-lifetime.v1 策略检查仍覆盖所有 schema25 及更新数据，未知策略不能通过格式升级绕过。没有修改旧工具的默认行为。

## 完整引用集合

checked_memory_source_rows 验证固定意图和已提交结果后，读取最多 101 行并核对完整集合。当前单条读取/Put 结果必须恰好有对应 scope、entry、version 的一条引用；失败及 Delete 必须为零条。不允许数据库表支持多行就隐式升级 v1 结果。

上下文重验从所有成功/失败的记忆操作出发，不只遍历存在的引用。因此删除引用本身不能让旧工具正文失去校验后继续提交。缺失、多余、错误版本、错误scope引用都会阻断模型调用。来源图构建也读取完整已验证集合，不能只取 query_row 的第一行。

## 验证

真实 SQLite 的旧布局迁移测试携带实际读取、原始模型输入/结果和来源绑定，验证升级不改写正文、不重放操作及新旧授权边界。额外/缺失引用故障注入必须在下一次模型调用前进入 content-free recovery_required；100/101 条引用的数据库边界使用明确拥有的测试事实验证。真实固定 schema25 程序创建文件编辑、批准和历史，再由新程序升级；旧程序非修改式拒绝另有 CLI 验证证据。

这些模型响应来自明确脚本替身，不是实际推理验收。发现 v2 的显式Run协议选择、版本目录/参数、每页引用、空页与游标生命周期、撤权/删除后的列表失效、桌面与真实模型测试仍待后续实现。此基础切片不能标 TK16/TK17 或完整记忆产品完成。
