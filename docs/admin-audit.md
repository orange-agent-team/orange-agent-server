# Scoped Admin audit reads (development slice)

Admin API0.1.3 implements scoped audit list/detail and `GET /admin/v1/session/permissions`. The latter returns current permissions for exactly one scope already held by the MFA administration session. The legacy session permission array is the intersection of its scopes, so it conservatively omits rights available only in a particular scope. Existing session/action/overview/node response shapes stay unchanged.

Audit records expose actor, scope, event type, occurrence time, optional action identity and original request correlation when it was captured. `result: recorded` denotes an immutable event record; it does not certify a Job, payment or cleanup result. Old records have `request_id: null`; event IDs are never substituted for missing original traces. Successful audit/scope-permission reads record their validated request ID, or a newly generated ID for that actual request, and return it in `X-Request-Id`. Other existing writers can still have an absent trace.

Migration0030 adds an ingestion identity, query indexes, optional request correlation and an opaque cursor store. It preserves original event columns and the append-only trigger. Legacy sequence allocation is not asserted to reconstruct historical arrival order. PostgreSQL17 permits identity column definitions in ADD COLUMN; see [the official ALTER TABLE reference](https://www.postgresql.org/docs/17/sql-altertable.html). Only dedicated local test databases have exercised this migration; no production migration timing or online-availability certification is claimed.

List pages contain at most200 records, with a fixed ingestion upper boundary and descending keyset traversal. Later reads and ordinary later inserts cannot expand that boundary. This is not an MVCC export snapshot: an older in-flight insertion can commit late, and refreshing starts a new browse. Events remain stored; this slice does not implement consistent export.

Cursor tokens are random and stored only by hash. The global sequence and authority fingerprint remain server-side. Tokens bind to the exact session, principal, effective scope permissions and policy version, expire after five minutes, and are capped at256 live tokens per principal. Expired metadata is pruned in bounded batches. Limits never grant access, refresh old authority or rewrite events.

List/detail and scope introspection recheck current authority before return, use no-store responses and expose no prompt, tool input, credential or support reason. Platform aggregation stays within its environment; other scopes match exactly. Unscoped historical identity events are not guessed into an environment. Unauthorized detail IDs return no foreign metadata. The API does not turn tenant or ordinary user roles into platform administrator roles.

The Admin consumer must import the fixed0.1.3 schema before using nullable audit traces and the new scope-permission endpoint. The previously prepared0.1.2 AuditEvent schema required a trace string; no old-schema compatibility claim is made for this newly implemented endpoint. An older backend missing scope introspection must be shown as unavailable rather than treating the incomplete legacy intersection as the full selected-scope grant.

`check-admin-audit.py` validates the two schema namespaces and local references, then creates its own loopback database, applies real migrations1–29, seeds legacy rows, applies30, and checks immutable fields, scopes, stable bounded pages, independent sessions, trace provenance, expiry and role revocation. Sessions are explicit fixtures; discovery is real. This is not a new MFA issuance, browser, production or all-Admin certification. Failed owned databases are retained with a private connection file; successful tests drop only their exact zero-connection database, without FORCE.

Optional `--admin-repo PATH --node PATH` runs the built consumer through actual Chrome/HTTPS/API/PostgreSQL with a parent-controlled committed revocation gate. It verifies that roles, legacy permission intersection and visible scope membership can remain unchanged while the selected scope loses audit access; another scope retains audit access. Browser sessions remain explicit fixtures, not new MFA issuance. This boundary has passed in a dedicated local database, which was dropped after zero remaining connections.
