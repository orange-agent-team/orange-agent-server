# 当前用户任务列表

GET `/api/v1/owners/{owner}/jobs`与原POST提交路径共存，支持after、limit（默认50、最大100）。每页在当前会话/owner/组织成员授权下，仅返回submitting_user_id匹配当前用户的任务元数据。组织admin并不自动获得他人任务列表。返回owner_id/user_id供客户端再次绑定身份。

游标按job_id排序，下一页使用最后一项ID；这是分页边界，不是固定时点快照或执行许可。PG0027为owner/user/job建立部分索引，避免按所有用户历史扫描。原001—0026迁移不改字节。

列表不读取提示词、结果或对象内容，也不要求重新获得消费授权。源已删除时原任务元数据仍是事实；读取输入/输出仍按独立的当前内容ACL拒绝。撤销会话或离开组织不能借分页恢复权限。

GET `/api/v1/owners/{owner}/jobs/by-invocation/{invocation}`只读核对原提交，返回当前提交者的Job及原quote_id，不返回源内容摘要或正文。浏览器不需要为了判断响应丢失而再次发起提交。404仅表示当前尚未读到记录，不能证明早先在途事务没有后续提交；恢复仍保留原Invocation和幂等键，不换键重跑。

`python3 scripts/check-user-jobs.py`用真实HTTP Router/PostgreSQL验证三项经真实预留的任务逐页恰好一次、同组织其他主体为空、页大小/未知参数拒绝、删除不恢复内容、撤权拒绝；身份和报价是明确夹具，不代表新真实登录、网络mTLS或模型执行。用于浏览器重开后查询原任务，不能触发模型重放。
