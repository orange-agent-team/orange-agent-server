# 版本与重新验收

变更发起人登记原决策 ID、事实来源、受影响的读者和生效版本。仓库维护者记录接口、存储、图和验证影响，验收负责人保存具体命令、提交和原始结果。新凭据出现后才更新相应事实或资格状态，原记录按版本保留。

| 变更示例 | 必须同步的产物与消费方 | 重新验收范围 |
|---|---|---|
| E03 新增模型失败类别 | Rust 接口、SQLite 迁移、CLI、共享源码清单、桌面固定引用和生成的 FRB；同步 Run 状态与恢复图 | 使用旧程序产生实际日志再升级；原 unknown 调用不得重放；错误记录仅原所有者读取；桌面重新读取同一调用 |
| 扩充收费计量单位或调价 | E01 金额、报价/计量契约、Admin 价格草稿及审批、用户 Web 确认稿、账本与结算图 | 旧报价、最大预留、真实输入输出计量、失败/取消、只结算一次，以及原消费来源恢复 |
| 增加地区或多 GPU 配置 | 区域路由、数据驻留策略、Worker 能力声明与租约、部署图及兼容矩阵 | 先做本地故障试验；在目标配置下验证旧租约失效、原设备回收、单写、删除传播和跨域接管 |
| 变更公开注册或企业身份策略 | 用户登录、租户角色、Admin 独立会话、运营流程与信任边界图 | 旧会话与撤权、同意和身份范围、跨租户访问、独立批准与审计留存 |

兼容判断需区分新增可选读字段、改变既有语义和新增危险写字段。最后两类必须有显式版本、旧端拒绝或经过验证的迁移路径。应用既有双人批准的产品操作仍按原权限执行。涉及生产基础设施或对外经营的变更另登记其实际授权。

[变更影响索引](change-index.json)列出原任务编号、仓库契约与验收命令 ID。每个图编号对应总计划 `plan/architecture/<编号>.md`、同名 Mermaid 源和 `assets/<编号>.svg`。修改图中关系时，三种表示一起检查。
