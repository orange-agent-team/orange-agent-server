# 原生捕获安全属性证据（schema17候选）

## 解决的问题

真实App Sandbox会给新暂存文件和通过rename保留的原件添加quarantine。外部源原本没有该标签时，原件的完整安全摘要会改变。仅允许暂存复制仍不足以完成发布；忽略安全属性会破坏恢复和历史读取的依据。

## 持久事实与边界

- `patch_capture_witnesses`：在stage2同一事务中写入，早于capture_intent。包含操作ID、已批准源安全摘要、原生标签flags/agent/event的分隔摘要、时间下界；没有属性明文。
- `patch_capture_receipts`：在stage4同一事务中记录实际保留原件安全摘要。stage4失败时不能留下伪造的完成回执。
- 两表不可更新或删除，插入必须处于当前Host epoch的dispatching操作及正确阶段。迁移不为旧记录生成见证，旧二进制拒绝schema17。
- 只有源原本无quarantine且新暂存有已识别原生标签才产生见证。比较要求新增标签之外的全部安全属性摘要等于原源摘要，标签权限字段摘要相同、时间不倒退或在未来。
- 原inode、父目录、字节数、mtime、mode和内容摘要继续检查。捕获后采用实际身份；后继比较不继续容忍任意标签漂移。
- 版本边携带捕获证据并与不可变持久记录核对。历史读取仍校验实际保留对象和当前目标，不能把变更后的原件误当已批准历史。
- 恢复检查使用同一证据判断原件身份。无见证、标签权限字段或其他安全属性改变会拒绝原件恢复。发布暂存额外要求安全摘要匹配stage2记录，不用内容匹配替代权限校验。

## 当前验证

实际签名沙盒CLI六场景通过：连续编辑及重开、新建后编辑、只读不能升级、撤权无效果、真实效果后无回执不重放、捕获后无stage4回执时凭先存证据识别原件且不自动恢复。源由驱动在专用测试容器临时目录创建，真实无quarantine；模型HTTP为明确替身。

Rust验证覆盖原生标签见证、捕获中断和重开恢复、历史源核验、其他权限变化/标签篡改/缺见证拒绝、暂存权限篡改拒绝以及旧schema迁移。普通CLI及固定旧7e115c3创建数据的真实兼容检查通过。完整日志保留在services_plan/execution的capture-witness-*文件。
