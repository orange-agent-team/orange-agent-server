# 资源动作与身份变化

本规格对应 PRD-001.02 至 PRD-001.04。表中的权限条件必须在接收请求或执行副作用的服务端成立。用户 Web 和 Admin 各自使用独立会话。

| 动作 | 可请求的主体 | 服务端检查与效果 |
|---|---|---|
| 上传、创建任务 | 当前个人用户，有创建权限的组织 Owner、Admin、Member | 逐项验证账户、成员关系、资源 ACL、预算授权、报价与幂等键。转写额外要求原始音频授权和指定节点。Viewer 和 Billing 无内容创建权限 |
| 读取任务元数据 | 原始提交者且当前仍可访问该账户 | 按用户及账户联合过滤列表、单个编号和调用编号。组织管理员只能在权限范围内管理成员 |
| 读取输入或结果 | 当前个人账户，或对对应资源有读取 ACL 的活跃成员 | 组织角色和资源 ACL 均需通过；Billing 没有内容读取权。结果检查源对象状态、来源权限及结果自身权限 |
| 取消任务 | 持有当前会话和对应提交身份的用户 | 排队任务在事务中退回原分桶。运行中只提出停止；确认未交付与真实资源回收后再处理冻结 |
| 删除输入 | 能写当前源对象的用户 | 即时撤销内容可见性；派生结果随后由服务端按引用和保留规则回收。任务和账本历史保留 |
| 提供推理 | 已登记的设备证书对应的提供方节点 | 匹配审核模型、观测、当前租约、节点状态和本地资源许可。每个设备只处理自己的分配 |
| 限制节点 | 有当前环境与资源范围管理权限的独立 Admin 主体 | 隔离使用 `nodes.quarantine`，提交控制意图和审计记录。执行与回收另有设备回执 |
| 审核开发价格 | 有定价权限的草稿作者、独立审批人、具执行权限的管理主体 | 服务端以固定条款和审核摘要匹配源草稿，并在生效时重验主管范围和独立审批资格 |
| 充值 | 个人或有组织购买权限的账户提出原币种订单 | 产品约定由支付适配器验证商户、金额、币种和签名回调后入账。现有开发余额没有真实收单认证 |
| 现金退款 | 原购买账户依据剩余可退的购买分桶请求；平台财务按范围复核 | Admin 契约要求 `payment.refund` 由 `payments.refund` 和独立的 `payments.refund.approve` 批准。真实商户执行、退款回调和对账仍待单列验收 |

### 身份变化

离职移除以当前成员关系生效，原始提交人字段和历史消费账户保持原值。资源授权同成员关系分别判断，再加入同一团队需要重新授予已撤销的 ACL。将成员降为 Billing 后，新的内容请求失去访问权。冻结组织会阻止新的组织操作和工作请求，预算冻结与账本保留原归属。需要终止的运行任务按实际分配和设备清理结果处理，历史收费事实保留原价格、提供方与交易编号。角色转移始终保留至少一位组织 Owner。

### 后端走查

| 身份 | 正向验收 | 越权或撤权验收 |
|---|---|---|
| 消费者 | 用有效报价冻结一次预算，按原调用恢复任务和结果 | 改用途、投影或原价格停用时拒绝冻结；撤回源授权时拒绝发布 |
| 提供者 | 设备以当前 mTLS 会话、租约和 Broker 授权读取音频、交付并清理 | 外部设备、旧租约、错误模型证据均无读取或提交权限 |
| 团队成员 | 创建者读取自己获准的内容，原提交人列出自己的任务 | 其他同团队主体查询已知任务编号取不到该任务，Billing 读取原内容被拒绝 |
| 管理员 | 操作员提交定价草稿，独立主体复核后执行 | 服务端拒绝自批；生效前撤销审批人的权限会进入受阻状态，恢复角色不会重启原批准 |

数据库与接口走查使用真实本地 PostgreSQL、HTTP 接口和独立会话夹具。设备走查另使用本机 mTLS、Whisper 和系统进程。测试记录区分开发行为与真实支付、目标硬件和生产身份颁发。
