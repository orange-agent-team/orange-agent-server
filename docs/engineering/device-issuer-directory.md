# 设备签发 CA 目录

管理接口 `GET /admin/v1/device-issuers` 显示所选范围内保留的签发记录。开发环境的平台管理员、安全操作员和审计员需要在所选平台或区域范围实际拥有 `device_issuers.read`。查询和成功读取的审计记录在同一 PostgreSQL 事务中完成。若权限在读取过程中到期，响应和审计写入一同回滚。

每行对应一个 CA 证书的 DER SHA-256。单独的公钥 SHA-256 来自开发签发进程对 CA 约束、固定指纹和实际私钥的匹配核验。以前已经签发的 CA 记录仍能查看；签发器尚未核对该 CA 时，公钥列为空。目录不存储私钥、令牌或证书正文。

| 字段 | 含义 |
|---|---|
| retained_certificates | 当前保留、归属本范围的签发记录数 |
| awaiting_exchange | 叶证书有效、授权仍有效并且尚未兑换的记录数 |
| active_credentials | 叶证书与已兑换凭据均有效、授权未撤销且节点未被撤销的记录数。节点可能离线 |
| expiring_within_hour | 上述有效凭据当中，将在一小时内到期的数量 |
| next_expiry_unix | 有效凭据的最近截止时间，同时核对证书期限与服务端凭据期限 |
| last_prepared_unix | 本范围内最近保存的签发时间 |

客户端按所选范围与 CA 摘要读取下一页。每次请求重新读取管理员权限。游标绑定主体、策略版本、权限集合、范围和原位置；它本身不授予读取权。数量随签发、兑换、撤权和时间变化。查询结果用于密钥运维，节点在线、允许执行模型、GPU 回收及生产信任根撤回另有独立判据。

## 永久撤回开发平台的设备签发公钥

平台值班人员先从目录复制签发公钥的 SHA-256。通过 `GET /admin/v1/device-issuer-keys/{key}?environment=dev&scope_kind=platform&scope_id=platform` 核对公钥、对应的 CA 证书数量、有效凭据、当前有效租约中使用该公钥的会话，以及无法追溯签发路径的会话。平台范围的 `device_issuers.read` 授权才可读取这份预览。各项数量随设备上线、退出和到期而变化。

创建 `device_issuer.withdraw` 操作时，传入预览的 `target_version`、相同公钥、关联工单及原因。持有 `device_issuers.withdraw` 的平台管理员申请，由另一位具备 `device_issuers.withdraw.approve` 和操作审批权限的管理员核对并批准。执行时服务端重新核对申请、双方权限、批准的内容摘要、版本、截止时间和操作者的二次认证。网络中断时，使用原操作编号和原幂等键核对结果。

执行成功后，同一公钥对应的所有已观测 CA 证书共享永久撤回记录。重新签发具有相同公钥的 CA 证书也无法恢复签发能力。签发、兑换及连接共用数据库事务锁。网关从实际校验成功的客户端证书路径计算摘要，包含中间 CA 和实际信任根。撤回使受影响会话及旧版无法确认路径的会话到期，其他已验证路径继续工作。需要恢复服务的设备使用独立新密钥签发并重新完成设备授权。部署升级时，已有会话在重新验证前保留未知路径，操作预览会单列其数量。

验收命令 `python3.12 scripts/check-device-issuer.py --withdraw-issuer --device-client` 使用临时 PostgreSQL、真实设备 CLI 和本机 mTLS 网关。测试创建相互独立的开发管理会话。生产签发、保管、批准人的实体身份及目标设备验证仍按部署环境单独记录。
