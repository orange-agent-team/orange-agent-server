# 作业事件快照与恢复

GET /api/v1/owners/{owner}/jobs/{job}/events 使用与作业状态相同的用户会话、当前账户范围和原提交者校验。读取快照、事件和保留边界在同一事务内完成，返回前再检查会话。即便具有同一组织的角色，也不能借用其他提交者的作业游标。

首次请求不带游标，返回 kind=snapshot，包含当前作业状态和状态版本；cursor 记录该快照已覆盖的 stream_id 与 after。历史作业从未创建事件流时，cursor 可为空。要补读事件，将这两个字段一起作为查询参数传入。after 是无前导零的十进制字符串，limit 默认 32，最大 64。kind=page 仅包含当前作业的有序元数据和下一游标。相同游标可以重复读取；调用方按 stream_id 与 seq 去重。

游标已被保留策略淘汰或属于不同流时，返回 kind=reset 和重新校验后的权威快照。客户端应清除从旧游标派生的临时展示，再以新快照和新游标继续。reset 不代表执行完成、费用结算、用户授权或再次触发作业。超前游标、非法十进制和未知参数返回输入错误。

schema 68 在真实执行开始、开始前拒绝及结果提交事件落库时，将可证明的 attempt_id 与事件一同提交。数据库核对尝试的 Job 与流的账户；先前没有显式来源的事件保留空值。响应提供 payload_digest，不提供输入内容、二进制结果、账户密钥或内部命令载荷。实际内容下载继续经过受控对象接口。
