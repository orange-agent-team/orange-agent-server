# 作业状态、版本和取消

用户读取自己提交且当前仍有权查看的作业时，GET /api/v1/owners/{owner}/jobs/{job} 的响应头 x-orange-job-version 提供十进制版本。版本与返回状态取自同一数据库行。取消请求可带 x-orange-expected-job-version，只接受一个正整数。现有客户端可继续省略该请求头。开发 API 的作业读取和取消也支持同样的头字段。

客户端需要重发不确定的取消时，应复用原幂等键和原版本；服务器先重新验证当前主体，再核对已提交的幂等记录。相同幂等键换用另一个版本会报冲突。新命令版本过期返回 412 STALE_JOB_VERSION，查询原任务后再决定是否发出新动作。陈旧、无效及重复请求不能产生额外解冻或账本记录。

| 对象 | 事件与允许的状态 | 中断后的结果 |
|---|---|---|
| Job | queued 可开始执行或在开始前取消；running 可请求取消或交付；cancelling 等待终止及独立回收证据；succeeded、failed、cancelled 终止执行 | 过期排队任务按原积分桶解冻。已开始的任务必须走执行取消与回收。执行终态不可回退，随后发生的财务结算单独产生新版本 |
| Attempt | offered 等待符合当前 session、epoch、fencing、期限的确认；确认成功为 started，开始前拒绝为 rejected；失联或无法证明效果为 unknown；明确回收后可 closed | 确定性输入错误不重放。过期尝试不能复活，unknown 不授予重试或资源复用权限 |
| Node | 注册后可进入在线；失联可转离线；draining、quarantined 由平台策略控制；revoked 需要独立的重新授权流程 | 心跳仅证明当前控制会话存活。主动排空不接新执行，隔离不能被普通心跳撤销，旧代策略不能覆盖新代策略 |

schema 67 给已有作业从版本 1 开始计数。数据库触发器维护对外可见字段的版本，重复无变化写入保留版本。并发完成与取消必须在锁定状态或条件更新上竞争；即使旧执行消息到达，数据库也拒绝把终态写回队列。无匹配容量时可排队至 deadline；模型确定性错误、旧租约、凭据撤销和未知回收均需按其事实结束或核对，不能无界重试。
