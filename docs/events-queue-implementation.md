# 持久通知与事务队列实施记录

2026-11-04；关联API-005/006。当前支持预算/Job通知，不是完整Run事件源、Worker控制连接或模型临时输出流。

## 领域提交与重放

预算创建、Job排队和排队取消在原领域事务中同时写入持久事件和outbox。每个owner/实体类型/实体ID对应独立stream；行锁分配递增序号，领域事务回滚时事件及序号变化一并回滚。事件ID与业务幂等键分开，资金操作不使用事件序号去重。

事件保存schema_version、stream/seq、实体、实际时间、载荷SHA-256、关联ID与可空因果ID。当前关联ID是本实体ID，尚未接入跨Run全链路因果追踪。序号通过规范十进制字符串传输；整数溢出、负数、前导零及超前游标均拒绝。

旧outbox中的载荷既有请求摘要字符串，也有取消状态说明。迁移005保留原载荷，统一计算原始UTF-8字节的SHA-256，不把状态说明伪装为已有摘要。首轮迁移因约束拒绝而回滚，修复后已验证；没有删除旧事件或放宽摘要格式。事件与outbox内容均不可UPDATE，只允许运输元数据变化。

开发消费者API新增：

- `GET /api/v1/event-streams?entity_kind=job&entity_id=<id>`：发现当前owner的通知流。
- `GET /api/v1/event-streams/<stream_id>?after=0&limit=50`：返回事件页及`next_cursor`，下一页把它作为after。

limit为1—200，所有响应no-store。当前仍使用明确的开发Bearer身份，未接通公共用户OIDC；不能因此称团队内容事件已完成授权。通知仅带元数据与摘要，客户端需要按当前权限查询实体快照，不能从通知解锁工具或认定资金已经结算。

维护函数`prune_delivered`只清理已经被队列持久接受的通知；未投递事件阻止清理。过期游标返回SNAPSHOT_REQUIRED；预算、账本和业务幂等记录不随通知保留期删除。尚无自动保留期调度或公共删除接口。

## PostgreSQL outbox/inbox

`EventQueue`是内部服务接口，订阅注册不能由普通用户请求直接调用。订阅绑定consumer、owner和事件类型。多发布者用SKIP LOCKED领取outbox，在一个数据库事务中向所有当前订阅者写入inbox并标记已接受；没有订阅的消息继续保留。接受标记不等于业务处理成功。

inbox使用consumer/event_id唯一身份，绑定原始载荷与完整事件头摘要。每次领取生成新租约ID，最长30秒，最多3次尝试；这是内部SQL通知租约，不替代Worker的45秒控制租约。暂时失败在2/4秒后有界重试；永久失败、第三次失败或最后租约超时写不可变死信。原消息保留，即使源通知已按保留期清理也能定位。

订阅撤销递增版本；重新启用不会使旧租约恢复有效。`begin_delivery`重新读取当前租约、订阅版本、载荷与摘要并持锁。业务SQL必须使用返回事务，`finish`在同一事务写完成标记；回滚或崩溃不会留下已改业务但未确认的半次处理。该重试协议**只覆盖同一PostgreSQL事务中的效果**，不能拿它自动重做外部工具、退款、HTTP写入等非事务副作用；这些仍依赖各自的持久操作身份与unknown核对。

当前没有启用自动发布daemon、调度器消费者或外部消息代理；消费者注册/领取/业务事务由服务实现调用，测试直接验证这些实际数据库端口。下一步需要把它们接到具体服务和进程生命周期，并补审计化死信人工处理、运维观测与容量测试，不能把当前结果当作完整Worker或支付认证。

## 验证

`python3 scripts/check.py --events --queue`执行3项持久事件和4项队列真实PostgreSQL测试。覆盖并发取消只有一条终态通知、逐页重放、跨owner/撤权拒绝、失败事务零事件、保留期边界、并发扇出一次、SQL效果与确认的提交/回滚、旧租约/旧订阅拒绝、有界重试/死信以及源通知清理后inbox不丢失。

事件保留期单测显式设置已投递夹具，只证明保留期；队列测试另通过真实publish_owner后清理并消费，证明持久接受链路。租约过期和重试时钟使用数据库中的受控时间夹具，不宣称已经过30天运行观察。`scripts/http-smoke.py`另外运行实际API进程，验证通知发现、游标续读和no-store。
