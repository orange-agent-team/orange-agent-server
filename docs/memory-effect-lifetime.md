# 记忆与文件效果的生命周期（schema25候选）

本候选移除了memory与create/edit不能同时启用的临时启动限制。它验证的是当前可用本地Rust/SQLite/文件工作线程边界，不是远端推理/GPU排空、其他OS或完整记忆产品认证。

## 生命周期归属

MemoryGrant拥有会话读取/效果计数，同时共享scope修订的计数。读取凭据、当前Run来源证明和实际写入工作线程持有相应lease。MemoryScopeRevoker由认证scope owner取得，能够在排队执行数据库变更前发出撤权信号；wait_drained等待实际持有者退出。取得新修订revoker也会包括仍活跃的先前修订，不能因数据库版本已经前进而漏掉旧消费者。

WorkspaceRevoker增加共享来源排空。注册工作区的正常Permit以及来源图中的间接使用者都进入原consent的计数；即使当前读取者使用另一个独立目录Grant，原consent撤回仍会停止其派生写入。已失效consent仍可取得仅用于等待的revoker，这不会恢复open_workspace权限。

Host应先缓存/取得正确revoker，发出信号，丢弃自身缓存读取凭据/准备对象，再等待串行数据变更与相关lease真正排空后确认关闭。信号不是确认，单个会话关闭也不代表整个scope的所有会话已关闭。

## 实际文件执行器

EffectGuard不可克隆，携带完整来源生命周期。新建文件时它随真实spawn_blocking工作线程移动，临时文件写入、发布及回执阶段会检查来源；直到线程/结果真正结束才释放。取消Future不释放仍在后台运行的来源计数。

编辑时来源guard归属PatchDispatch，进入已有的逐阶段live检查；来源观察器将撤权传播给独立读写授权。观察器的克隆只保存取消状态，不持有读取lease，因此不会反过来阻塞排空。

Journal锁仍对应一个实际open-file description，没有暴露/复制锁fd。显式效果lease可以延长同一锁的所有权，防止Journal对象已丢弃但派生工作线程尚在时出现新Host。普通重复fd仍不能伪造锁所有权；只有有意创建的效果生命周期能够保留它。

## API与批准

- approve_agent_creation_authorized接受显式AgentAuthority并校验所有当前来源。
- agent_patch_preview_authorized与approve_agent_editing_authorized提供混合能力下的真实差异预览与批准。
- 原接口仍服务不含记忆的既有Run，不会隐式恢复记忆权限。
- Runtime内含记忆权限的创建/编辑不能通过缺少EffectGuard的低层执行入口绕过来源生命周期。
- 工作区新建/编辑结果也可以成为后续记忆的来源：核对真实回执后，重新读取实际发布的文件并匹配结果摘要/大小。后续外部修改使派生记忆失效。

## 格式边界与恢复

schema25增加不可修改的runtime_effect_policy，声明source-lifetime.v1。它是执行语义边界：旧程序不能打开一个包含混合操作的新Run，却按不具备来源排空的旧执行器处理。未知策略在改写数据库前拒绝。

首次compat检查暴露了未升级格式的问题：旧schema24程序确实能打开仍标24的数据。保留原“旧版必须拒绝且不修改”的验收断言，新增明确格式迁移后真实检查通过。没有把错误接受改写成成功条件。
