# 转写结果提交与读取

输出能力与输入能力分别协商。transcription_output_version=1 要求当前会话支持受控音频输入和流式输出。Worker 提交完整文档，MIME 为 application/vnd.orange.transcription+json。文本模型的输出头不能用于转写任务，反之亦然。

平台重新读取并校验源版本的完整字节摘要，将最终文档与持久化授权中的原始及标准化采样、时长、模型、语言、配置摘要和请求投影逐项比对。输出需有完整文本和单调的毫秒时间段，最多 10,000 段。文档上限 2 MiB；原文本提交仍适用原 1 MiB 限制。临时对象落盘后，在同一 PostgreSQL 事务中复核权限并建立 available 版本、结果回执、转写计量事实及成功终态。一份 Job 最多有一个已提交结果。

用户读取已交付的结果取决于当下的源对象和结果对象权限。删除源后会立即拒绝访问结果，回收器随后撤下派生对象。提交过程遇到撤权或不一致的计量时，刚写入的内容仍是私有暂存数据，由回收器清理。受控 Worker 的本地持久发送路径仍要求真实 CPU 回收记录；服务端提交成功和设备回收各自维护单独证据。

真实测试用独立的开发队列与零金额报价夹具启动 Job，然后经 Broker、mTLS 读音频并在提供方运行 Whisper。测试用该次真实 ACK 的身份发送完整输出，验证重复发送与查询只得到同一回执，以及错误时长和物理写入后撤权均不发布结果。Chrome 读取实际提交的版本，显示文本、语言和时间段，源删除后清除内容。该组公开录音用例与开发积分的独立订单一起回归。[数据契约](../contracts/openapi/artifacts.v1.json) · [设备协议](../contracts/proto/worker.proto)

## 开发积分转写订单

迁移 55 在开发节点上启用按实际解码毫秒计量的版本化价格。准入需要同时支持音频输入、转写输出和 CPU 清理协议的当前会话，以及审核配置、有效授权、提供方钱包和显式启用的开发价格。测试通过数据库夹具准备准入价格。价格维护的生产审批及真实资金认证仍待验收。

用户先读取授权下的价格，再以独立请求编号取得最长 60 秒有效的报价。服务端用整数向上取整计算预留上限，公式为 `ceil(源时长毫秒 × 每分钟费率 / 60000)`。报价关联已选节点、配置、观测、授权人、源版本、预算和调用编号。报价只读取预算余量。用户确认后，通过既有 Job 接口以 transcription 用途提交，事务同时冻结预算与钱包。在排队时取消能全额解冻。已确认的交付通过不可变计量事实结算，重新提交同一结果或重试结算沿用原交易。

本地验收使用 11,000 毫秒录音、每分钟 12,000 个开发积分最小单位和 20% 平台费。真实 PostgreSQL、mTLS 和模型输出验证了 2,200 的预留与扣减、440 的平台费和 1,760 的提供方待入账。受控提供方的常驻进程调度与清理回执仍须单独验收。

恢复入口为授权详情、原 invocation 的 Job 查询和任务列表。已发生预留且浏览器响应丢失时，同一用户可查询原任务。对象服务将已关闭写入器的失败转写标为可立即回收，物理移除两份私有文件后才释放容量。进程中断导致写入状态不确定时保留既有过期租约与孤儿回收流程。
