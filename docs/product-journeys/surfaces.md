# 界面、服务状态与审计对应

| 流程 | 用户确认的具体内容 | 服务端与审计证据 | 当前实际入口 |
|---|---|---|---|
| 租用 | 报价、指定提供方、预算与最大预留；用户点击提交 | 原调用对应的报价和 Job、预留分桶、输出回执以及 `job.settled` 事件 | 用户 Web 的个人任务页及团队预算转写页 |
| 供给 | 本地配置允许贡献，明确审核配置和单个 CPU 槽 | mTLS 会话代次、分配、启动租约、Broker 槽代次、清理回执与提供方待入账余额 | 本机 `orange-worker` 正式进程入口；当前物理验收为 macOS CPU |
| 团队 | 收件人核对组织和角色后接受；所有者确认硬上限，管理者确认受益成员和额度 | `team_audit` 的 `invitation.issued`、`invitation.accepted`、`budget.policy_changed` 和 `budget.allocated`，组织 Job 使用组织所有者和成员预算根 | 用户 Web 的组织列表、邀请箱、团队预算和团队任务 |
| 隐私 | 选择具体上传版本和远程接收节点，勾选单次许可和过期时间 | `transcription_input_grants` 的源版本、角色与节点绑定；撤回记录、原始源状态和派生结果访问检查 | 用户 Web 音频预检和授权页面，桌面本地文件许可为单独权限边界 |
| 充值 | 明示币种最小单位、档位对应的微积分；用户单独确认派发测试支付会话 | 订单、签名 Inbox、同一会话与付款凭证、唯一履约交易和 `sandbox_purchase.credited` | 用户 Web 账户与原订单历史；浏览器回跳只查询原单 |
| 退款 | 用户确认原单可退现金和相应积分冻结；独立财务主体核对原单、现金与冻结数量 | `sandbox_refund.held`、审批记录、原商户退款对象、唯一终态凭证与 `sandbox_refund.finalized` | 用户 Web 原单退款与独立 Admin 对账事项、审批页 |

完整演练使用真实用户会话接口、HTTPS 浏览器、数据库、模型、Worker 和平台账本。身份、设备登记及测试商户协议提供隔离的开发输入。第三方商户沙箱认证、两台物理主机、GPU、公开注册与真实收费继续采用各自的验收门槛。
