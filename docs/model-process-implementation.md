# 本机CPU模型进程与私有IPC

日期：2026-11-05（Asia/Shanghai）。当前是Unix进程管理切片，不是实际模型推理或GPU回收认证。

`orange-model-runtime::supervisor`由可信安装器/审核profile调用，校验绝对程序/模型路径、完整SHA-256、大小、GGUF标识与文件类型。拒绝链接和多硬链接文件，不接受模型生成的命令或额外参数。启动参数固定CPU路径、2线程、1并发槽、GPU layers=0；二进制本身必须来自经核验的CPU-only构建，不能把参数当作任意GPU二进制的隔离证明。

固定llama.cpp源码`b74298c`实际支持以`.sock`结尾的Unix socket路径。新客户端使用私有socket、禁止代理/重定向，并保持既有输入计量、有界SSE和完整响应候选规则。运行目录必须0700、socket路径最长100字节；宿主必须把该目录登记为私有区域并置于所有用户工作区之外，不能拿普通用户工作目录作为运行目录。

启动先取得真实文件锁并检查旧进程记录，再验证制品、写私有API key和starting记录。进程继承执行锁到stdin；已核验的后端profile必须保留该描述符。只有私有health就绪且子进程仍受监督，才记录ready。启动期限由profile限定在1～120秒；测试正常冷启动使用5秒，故障用例明确缩短到1秒。

`shutdown`先记录draining，终止并等待自己启动的子进程，再清理socket/key、持久化stopped并释放锁。`poll_status`会读取真实退出状态，不把缓存的ready当成存活证据。stderr/stdout当前不对外转发，失败以结构化状态和退出码表达；完整的有界脱敏日志后续补充。

Future被丢弃或对象Drop只记录unknown并请求终止，不伪造stopped回执。父进程异常退出后，仍运行的子进程保有继承锁，新实例不能占用；即使随后退出，缺少stopped回执也要求恢复核对。**这不是自动孤儿进程恢复实现**：当前没有根据裸PID杀进程、强制清除未知记录或伪造回收证据的接口。生产完整监督仍须补齐父子监督协议、恢复身份核验、诊断及目标OS路径。

`python3 scripts/check-model-process.py`运行真实子进程、文件锁和Unix socket，覆盖摘要/权限拒绝、私有IPC、明确退出回收、未就绪/启动失败、Drop、启动取消、实际退出查询与父进程被终止后的锁保持。后端是仅在`process-test-fixture` feature下构建的显式测试程序，GGUF样例也是假数据；该程序不随默认发行构建启动。测试中的专用退出端点仅用于清理测试孤儿，不存在于生产llama.cpp接口。

真实固定GGUF仍因网络条件未获得，因此不得把上述测试当作模型加载/推理成功。Windows监督/IPC、真实GPU、自动孤儿恢复和完整桌面模型管理仍未完成。
