# 本机CPU模型进程与私有IPC

日期：2026-11-05（Asia/Shanghai）。当前是Unix进程管理切片，不是实际模型推理或GPU回收认证。

`orange-model-runtime::supervisor`由可信安装器/审核profile调用，校验绝对程序/模型路径、完整SHA-256、大小、GGUF标识与文件类型。拒绝链接和多硬链接文件，不接受模型生成的命令或额外参数。启动参数固定CPU路径、2线程、1并发槽、GPU layers=0；二进制本身必须来自经核验的CPU-only构建，不能把参数当作任意GPU二进制的隔离证明。

固定llama.cpp源码`b74298c`实际支持以`.sock`结尾的Unix socket路径。新客户端使用私有socket、禁止代理/重定向，并保持既有输入计量、有界SSE和完整响应候选规则。运行目录必须0700、socket路径最长100字节；宿主必须把该目录登记为私有区域并置于所有用户工作区之外，不能拿普通用户工作目录作为运行目录。

启动先取得真实文件锁并检查旧进程记录，再验证制品、写私有API key和starting记录。进程继承执行锁到stdin；已核验的后端profile必须保留该描述符。只有私有health就绪且子进程仍受监督，才记录ready。启动期限由profile限定在1～120秒；测试正常冷启动使用5秒，故障用例明确缩短到1秒。

`shutdown`先记录draining，终止并等待自己启动的子进程，再清理socket/key、持久化stopped并释放锁。`poll_status`会读取真实退出状态，不把缓存的ready当成存活证据。stderr/stdout当前不对外转发，失败以结构化状态和退出码表达；完整的有界脱敏日志后续补充。

Future被丢弃或对象Drop只记录unknown并请求终止，不伪造stopped回执。直接监督者异常退出后，仍运行的子进程保有继承锁，新实例不能占用；即使随后退出，缺少stopped回执也要求恢复核对。当前没有根据裸PID杀进程、强制清除未知记录或伪造回收证据的接口。

新增用户态`orange-model-host`：读取0700目录中的0600配置，stdin只接受有界`ping`/`shutdown`行，stdout只输出版本化进程记录。父界面须每30秒内发送心跳，控制读取从加载阶段就启动。EOF、明确停止、坏帧或心跳失联都会走确认退出的清理流程；界面崩溃和加载中取消已用真实进程验证。监督程序自身被杀则仍按上段隔离，不宣称已实现所有孤儿恢复。Tokio stdin的阻塞线程在进程结束时有退出上限，不让读取遗留控制行无限阻塞退出。

配置可选control_nonce用于之后的私有命名控制通道。启用后，先在五秒内验证父端认证帧，再允许获取模型执行锁或启动模型；错误、缺失或过长认证不会产生模型进程效果。继承匿名管道模式不需要额外nonce，保持既有接口兼容。配置打开后再次核对FD身份、类型、权限和大小，避免仅依赖打开前的路径检查。

`python3 scripts/check-model-process.py`运行14项真实子进程/文件锁/Unix socket测试，除原有清理与隔离边界外，还覆盖启动前控制认证和认证失败无模型效果。后端仅在process-test-fixture下构建，GGUF为明确假数据，不代表真实推理。专用退出端点只用于测试孤儿，不属于生产llama.cpp接口。

真实`check-local-model.py`已改用监督程序、私有socket与控制心跳，避免共享开发TCP端口及未经确认的进程回收；仍必须先有准确SHA的官方GGUF和固定CPU构建。缺模型时不启动任何后端。

真实固定GGUF仍因网络条件未获得，因此不得把上述测试当作模型加载/推理成功。Windows监督/IPC、真实GPU、监督器自身崩溃后的恢复身份核验、完整诊断及桌面模型管理仍未完成。
