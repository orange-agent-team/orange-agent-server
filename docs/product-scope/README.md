# 功能、交付阶段和验收归属

产品经理可在 core.json 按业务能力查找负责人对应的原始实施步骤、历史里程碑、联合门禁和预期结果。能力条目涵盖消费、供给、团队、隐私、充值和退款六条用户流程，也包含托管工作区和独立管理后台。validation_unit 指向已有的局部验收入口；查明是否通过时需读取对应版本的测试结果。真实收费和公开注册须在授权地区通过 M4、G3 及发布条件，同时取得独立发布授权。[业务能力与延期项目](core.json)

| 产品里程碑 | 可以验收的范围 |
|---|---|
| M0 | 主体、权限、协议与隔离探针 |
| M1 | 离线桌面、本地文本任务、操作恢复、隐私路由 |
| M2 | 开发身份、远程执行、节点供给、租约与测试积分 |
| M3 | 四种模态、团队归属、贡献收益和节点风控 |
| M4 | 公开注册、原路充值退款与发布维护，需核对真实商户、设备、许可和运维凭证 |
| M5 | 后续平台能力分别立项，语音合成单独验收 |

catalog.json 逐项保存工具注册名、连接器动作、场景名称和适用边界。work 对应原始子步骤或后续工程工作包，acceptance 对应范围验收组；evidence_key 为该条目单独保留的凭证索引。G1 首批 16 个工具在 G3 继续认证。下表各列都是当期累计数量，连接器是动作分组。[逐项清单和角色权限表](catalog.json)

| G3 | 24 | 6 | 26 | 8 |

例如，TK-05 的实施归属是 AG-007.02，验收时按授权工作区的原摘要预览、批准并应用补丁，另验证并发冲突。CN-05/query_view 仅面向授权只读视图。AU-03 的验收产物是授权录音的转写文本和时间段。每个平台、模型、硬件、协议、触发器、扩展包和兼容单元的条件保存在 profiles，团队五角色对具体动作的权限保存在 team_permissions。设备存在和真实设备认证分别登记。

## 核验和更新

在服务端仓库运行 `python3 scripts/check-product-scope.py` 即可离线核验快照。分别检查四个原始步骤使用 `--step entries`、`--step milestones`、`--step exclusions` 或 `--step coverage`。在四仓联合工作区给 coverage 额外传入 `--planning-root ..`，会逐项与共享台账比对，检查原始父任务、子步骤、后续切片与验收入口。只有主动传入 `--refresh` 才会重新生成清单；待晋升的执行单元可以通过 `--execution-manifest` 指定相应待发布清单。

合并或恢复时，运行日志需包含源版本、环境、具体能力、原始输入与观察结果。商户替身、CPU 与目标 GPU、单机故障与跨区接管分别出证。PRD-003 的通过条件是范围与责任可追踪；功能认证随各自实现和发布门禁推进。
