# 记忆因果来源候选（schema24，尚未完成整个记忆功能）

该候选替代schema23中的粗略源Run过滤：记忆现在可以从实际已批准读取的工作区文本生成，并在之后的读取、模型请求与历史展示前验证来源。模型输送测试仍为明确替身；没有真实模型或桌面集成认证。

## 绑定真实输入，而非推测依赖

Run注册时保存原始工作区的物理resource身份、owner、environment、policy，以及存在时的持久workspace consent与版本。后续选择同名目录或同内容目录不能改变该绑定。旧数据库没有这些记录时，不根据用户后来选的目录补造历史物理身份。

`runtime_memory_lineage`保存某个memory_write实际对应的ModelInvocation输入摘要及无正文的来源引用。读取的是已经提交且校验过的模型请求，其中每条Tool消息必须匹配相同Run内已提交操作的实际model_result或真实用户问答记录。失败消息不冒充数据来源。模型输入中未出现的后续读取不会被误记成依赖。

当前来源类型：

- Workspace：原owner/Run/Operation、物理root身份、结果摘要。支持已有只读文件/目录/文件名搜索/文本搜索操作。
- Memory：scope、entry、精确版本，并递归核对该版本的来源图。依赖图每份最多128条引用/64KiB，遍历最多256节点、深度16，检查路径循环。

UserDeclaration代表可信Host记录的用户声明；模型执行始终强制ModelInference。Runtime外无可证明工具来源的推断不能被伪装成已验证派生内容。

## 当前授权与版本

`AgentAuthority.with_source_workspaces`及`with_source_memories`接收调用方已明确取得的能力，仅供来源证明，不扩展模型可调用工具的scope。验证器不会自行打开保存的目录路径或重授权限。

工作区来源同时要求：保存的原始consent仍有效、当前读取者的真实目录能力有效、物理resource相同、重新执行原只读请求得到相同结果摘要。当前actor/policy必须匹配本次读取者，不能拿其他actor的能力充数。记忆来源要求对应scope当前权限及所引用版本有效；源记忆删除或禁用会阻止派生记忆再进入模型/历史展示。

来源读取凭据保持到提交/丢弃结果。模型返回后再验证来源，变化则不提交派生回应。写事实事务内部也检查来源权限和记忆版本；针对当前精确获批条目的合法版本转换只在内部事务检查中允许，不向普通读取开放旧版本。

这些是明确版本的读取快照和应用授权检查，不等同于排除所有外部文件写入。其他程序仍可能在最后检查后修改文件；下一次使用会重新验证，不能据此宣称全文件系统CAS或硬实时一致性。

## 预览与存储旁路

AgentMemoryPreview增加provenance与approval_digest。真正的用户批准摘要覆盖原操作、参数、环境、Core草稿摘要及来源图摘要；仅提交旧payload摘要不能批准新来源。实际Core回执仍使用原草稿摘要，恢复核对不会将两个概念混用。

Runtime草稿的创建与Operation关联现在位于同一SQLite事务，绑定失败不留下可由普通Store绕过的孤立草稿。原始Store接口不再允许直接创建/审阅Runtime来源草稿；Engine通过受限内部接口取得数据，并在源证明成立后才返回内容。

原始Store读/列表拒绝需要来源授权的正文和标题。空来源声明还会核对实际模型请求中的工具历史，不能靠把来源数组置空并重新计算摘要绕过。对用户管理界面需要提供来源感知的读取/分页入口；不能直接复用原始Store读方法。

## 兼容和未完成项

schema23 CLI的实际编辑/批准数据升级24，以及旧程序不修改式拒绝已经验证。旧独立/记忆来源可以从不可变模型输入核对；缺少旧工作区物理证明时明确拒绝，不补造。

混合memory+create/edit仍未开放：需要把来源撤回、效果取消与实际后台文件线程排空接起来。还需完成当前Run自身记忆更新的历史处理、发现/列表的逐条目来源、知识/连接器提供方、管理读取/FRB/界面、实际LLM和跨端验收。不存在“只支持独立用户事实”的最终范围缩减；这些仍是必须完成的原计划工作。

## 验证

真实SQLite和临时文件测试包含：实际文件→记忆；跨Run/跨目录读取；错误目录同内容拒绝；源文件变化；旧授权在Journal关闭后失效；明确重新选择源能力；持久源授权撤回不能由新的裸目录能力绕过；因果输入排除未来无关读取；跨scope传递依赖及删除祖先；仅证明用授权不成为模型新权限；草稿绑定故障无孤儿；事务内来源ACL故障回滚；重算摘要的假空来源拒绝；生成中源变化不提交回应。统一证据在memory-provenance-staging.json和memory-provenance-*日志。
