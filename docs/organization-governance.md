# 团队邀请与消费额度

用户通过组织页面进入管理，收件人通过「我的团队邀请」取得自己的成员标识和待处理邀请。当前站内邀请发给一个已登记用户，由该用户的实际会话确认。创建邀请不增加成员、不共享原有文件，也不分配积分。组织 Owner 可邀请任一团队角色，Admin 可邀请普通 Member、Billing 或 Viewer。对既有成员的角色变更使用当前组织策略版本；移除最后一位 Owner 会被拒绝。[团队接口契约](../contracts/openapi/team-governance.v1.json)

邀请具有稳定编号、固定角色和截止时间。领取时再次验证发起人角色、收件人、组织状态、成员上限和有效期，然后在同一事务中修改成员关系并记录领取。调低邀请人的权限或停用组织会撤销未领取的相关邀请；恢复角色不会重启旧邀请。成员退出或失去内容创建角色时，旧预算提交授权撤销，重新加入后需要新的明确授权。Web 在发出治理请求前保存原操作身份，丢失响应后用同一编号恢复。

硬预算使用整数微积分。Owner 设定允许的最高上限和生效硬上限，Admin 可以在 Owner 允许的范围内调整生效上限。成员额度来自同一组织容量，每笔额度对应独立预算根并关联受益成员。分配不往组织或个人钱包写入余额。活跃预算占用其上限，关闭中的预算和已关闭预算按已消费与尚未释放的预留计入。已有预算会在升级时纳入总量，已有组织在 Owner 首次明确设置之前保留原行为。数据库在同一事务内防止并发分配突破已设上限。

成员只能读取获准的额度，Billing 可读团队预算资料；内容共享仍取决于内容 ACL。减少额度时不能低于已消费与冻结之和。调整请求核对原授权版本，撤销和重新授权会改变该版本。用户任务通过既有 Job 接口扣减组织钱包。在本地验收中，分配额度后组织余额仍为零；单独提供开发余额后，成员的实际 400 微积分任务只冻结组织钱包，取消后按原来源返回。用户 Web 可从个人组织列表进入管理与预算页。

运行 `python3 scripts/check-team-memberships.py --web-repo ../orange-agent-web`，可验证两个独立 Chrome 用户会话、真实 PostgreSQL、成员竞争、撤权、原编号重试及旧预算迁移。身份会话为隔离开发夹具，邮件邀请与外部企业身份认证另行验证。

成员可从本人获准的额度进入团队转写，页面固定当前组织与预算编号，按用户确认的上传版本、地区和节点取得报价。成功结果在组织范围内的原提交人任务页面读取。服务端对团队输入、预算和结果各自检查当前权限；个人账户会话仍是同一份身份，不会被替换成组织身份。[六条用户流程](product-journeys/README.md)
