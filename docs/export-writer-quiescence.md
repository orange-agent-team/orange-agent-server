# 导出写入者停止证明

schema19新增不可修改/删除的export_writer_bindings。目标不是清理文件，而是在未来明确处置前排除本应用旧导出线程仍可能写入的情况；其他程序写入、对象内容和命名空间变化仍需要另外的控制。

## 派发与锁生命周期

精确批准后，在同一派发事务中以create_new/0600/O_NOFOLLOW创建私有.export-writer-<export UUID>.lease，持有独占OS文件锁，写入并同步32字节随机绑定数据，并保存设备/inode/绑定摘要。先完成记录与派发提交，才允许目标目录效果。

WriterLease直接移入实际发布线程，跨越写入、同步、排他重命名和验证；入口、最终发布前及返回前复核原锁文件身份。没有显式unlock或公开clone/原始FD接口：关闭Journal、取消调用Future或把状态变成unknown都不会提前释放仍由后台线程持有的锁。任何仍持有同一打开文件描述的继承者也必须结束，锁才可重新取得。

## 获取证明

acquire_export_quiescence需要当前独立ExportInspectionGrant，记录必须为unknown或succeeded。它只打开原登记的私有文件，不创建/替换缺失文件，不按PID推断，不强制解锁。检查单链接、私有权限、设备/inode和绑定内容摘要，非阻塞取得独占锁后再次验证。

返回不可序列化的ExportQuiescence，调用者必须持有它直到相应受保护流程结束。check在读取授权撤销或锁路径/身份变化后拒绝；它也持有读租约，关闭检查时必须先丢弃缓存证明，再等排空。证明本身不包含目标写入或删除能力。

原schema18记录没有writer binding；迁移保持原数据且不会补造证明，仍允许只读检查，但停止确认会拒绝。未来UI必须区分“有匹配文件”与“已持有注册写入者锁”。

## 已验证

- 204项Runtime测试及严格Clippy通过，export-writer-runtime-full.log。
- 实际发布线程在暂存后暂停；取消拥有Journal的任务并重开Journal，记录虽为unknown且暂存匹配，仍无法获取证明。只有旧线程退出后才能获取；第二个持有者和撤权均被拒绝。
- 真实子进程持有原锁时当前进程不能获取证明；子进程正常退出后才可以。只管理直接创建的Child句柄，不依据旧PID清理。
- 同字节替换为另一inode被拒绝，已有证明也失效；恢复原inode仍受原独占锁约束。binding不可改写/删除；旧schema18形状迁移不生成绑定。
- 固定84d797c/schema18旧CLI实际编辑和批准记录升级19后保留，旧CLI再打开非修改式拒绝，export-writer-schema18-compatibility.log。

## 仍需实现

本增量没有删除、回收、归档额度释放或成功补记。后续需独立写授权、精确对象预览/批准、持久处置派发与回执、目标命名空间竞态处理和失败后的状态保留，并验证实际签名桌面路径。仅持有本应用的写入者锁不排除外部程序修改目标，不能宣称全局内容CAS或物理空间已回收。

如果事务在私有锁创建后、提交前失败，可能保留未绑定的私有锁文件；不会复用它或据此确认停止，也不会自动删除用户目标。此类私有元数据整理需单独审计，不改变已派发操作的不重放规则。
