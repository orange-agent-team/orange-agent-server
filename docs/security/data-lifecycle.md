# 数据归属、存放位置与删除责任

| 数据 | 业务所有者 | 当前存放位置与读取方 | 删除或撤销责任 |
|---|---|---|---|
| 原始输入 | 选择文件或提交任务的个人，或拥有任务的组织。原文件的系统权限仍由设备用户管理。 | 本地任务按授权从设备读取。远程任务先形成上传预览，获得确认后通过用户 API 上传。OpenDAL 保存字节，PostgreSQL 保存不可变版本、所有者、引用及传输记录。获授权的 Worker 可在执行期间收到明文。 | 用户或获授权的成员请求删除。E07 校验当前权限，写入删除标记后禁止新读取。用户删除接口在同一事务内检查活跃输入引用，冲突时返回 409 ARTIFACT_IN_USE。先取消并核对任务，再重试删除。撤销授权属于独立流程；清理方继续尊重物理引用。对象维护程序确认物理清理。设备用户管理其原文件。 |
| 生成产物 | 付费任务绑定的个人或团队账户。节点提供者仅有执行权限。 | 平台私有对象根保存字节，数据库把产物与作业、尝试、不可变版本和原输入关联。下载单独检查当前读取权。 | E07 按源数据撤销派生结果访问，并由维护程序清理对象。已由用户下载的副本归该设备管理。 |
| 会话与运行记录 | 桌面资料归当前设备用户，托管运行归其提交者所属账户。登录会话分别归用户和管理主体。 | 桌面 SQLite 私有目录保存运行日志与操作状态。托管 Run 由 E07 存入 PostgreSQL。浏览器使用独立的用户或 Admin cookie，服务端记录会话状态。 | 用户可注销自己的会话；Admin 有独立的注销操作。云运行撤回、工作区清理、本地数据退出分别处理。注销不会替代取消作业或撤销已发的个人密钥。 |
| 领域事件与投递队列 | 事件流归持有实体的账户。运维方保管投递与消费进度。 | PostgreSQL 的事件流、事件、outbox 和 inbox 保有各自的事实。对终端重放的作业信封包含序列和摘要，内容读取走独立接口。 | E07 运维按流逐批推进保留水位，在尚未交付的通知前停止。旧游标失效后客户端重新取得当前授权下的快照。 |
| 遥测 | 由平台运维负责采集与清理。 | 开发 API 在内存聚合请求数与时延；私有指标端点供获授权的采集器读取。这两个指标仅使用服务角色、方法和 HTTP 状态类别标签。外部采集器的地址、样本和保存期限依部署而定。 | 采集器运营方清理其后端与备份；本机服务停止会释放进程内样本。环境负责人需要另外验证集中式保留设置。 |
| 预算与账本 | 钱包、预算和交易归固定账户。平台财务维护具有业务唯一键的记账事实。 | PostgreSQL 保存预算、冻结、交易和复式分录。已封账交易保留原 owner 与资金桶。 | 财务按授权进行冲正和对账。内容删除和成员离职不删除分录。经营主体、地区及法定保留期需单独确认；项目未给账本设置通用删除期限。 |
| 凭证与授权 | 用户管理个人密钥，平台安全管理员管理 Admin 身份和节点登记，设备所有者保管节点私钥。 | 完整个人密钥只在签发或使用时交给持有人。库内存储 verifier、scope、到期与撤销时间；节点登记保存证书指纹和有效期，私钥留在受控设备。OIDC 客户端凭据由部署方通过私有配置提供。 | 用户撤销或换发个人密钥。E07 持久保留撤销依据以处理重试。节点登记方撤销证书，部署方轮换其 OIDC 凭据。终端负责清除本机副本。 |

## 时间与恢复

原路线要求输入及中间对象从最后活跃引用释放后保留 24 小时，输出从交付后保留 24 小时，运维元数据目标为 30 天。在当前开发包中，暂存、用户删除、派生结果撤销以及物理回收有各自的触发点。当前开发服务在私有对象根定期检查到期版本，先记录策略过期，再异步清理对应字节。30 天也需要每个实际采集后端提供配置和观测。

恢复数据库和对象根后，维护方应先核对撤销、删除、成员权限和事件水位，再开放访问。跨域备份保管位置、备份寿命、真实商户记录和用户已导出副本分开登记。真实四域驻留仍需部署证据。

机器可读清单记录每类数据的负责人、存储位置及真实数据库锚点。检查命令迁移一个临时 PostgreSQL 数据库，并逐项核对列和归属外键。[数据锚点](data-lifecycle.json) · [数据库清理](../database/transactions-and-retention.md) · [作业事件](../engineering/owned-job-events.md) · [身份撤销](../engineering/identity-deadlines.md)

```sh
python3.12 scripts/check-storage-contract.py --section lifecycle
```

### 查询某一版本的保留期限

具备该对象当前读取权的用户可请求 `GET /api/v1/owners/{owner}/uploads/{upload}/retention`。返回对象和版本标识、起算依据、起算时间和预计到期时间。时间为十进制 Unix 秒，接口不返回对象正文。暂存从创建起计一小时。新发布且从未引用的输入从发布起计二十四小时。活动输入不显示固定到期时间；释放最后一个作业、运行或 pin 后重新起算。完成输出始终以不可变的响应提交时间起算。旧数据库无法重建历史输入的最后释放时间，第一次升级为这类输入建立显式过渡期。已经逻辑删除的对象不显示新的保留期限。

到期后，新内容读取与新增引用必须通过服务端时钟检查。维护任务在私有对象根复核活动引用，按批写入策略过期事实，确认删除对应的公开副本与暂存副本后释放配额。用户主动撤销和策略过期分别记账。系统备份与用户已导出的副本仍需各自的处理凭据。[契约](../../contracts/openapi/artifacts.v1.json)
