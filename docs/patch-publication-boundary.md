# 现有文件编辑发布边界（未开放工具）

当前实现停留在实际源预览、独立持久编辑同意、精确批准、安全属性绑定，以及发布前的持久化保留计划。普通 Agent、CLI、Desktop 尚未注册 apply_patch；没有因这些 API 而修改工作区文件。

schema10 的 `editing_publications` 与 operation 的 intended→dispatching 在同一个 SQLite FULL 同步事务中提交。记录包含操作、批准预览摘要、目标路径、两个独立随机且受路径策略保护的暂存/原文件保留名称、原/结果 SHA，以及保留容量；另有资源身份和 Host epoch。记录不可更新或删除，事务失败时操作仍为 intended，原批准保留。

返回的 `PatchDispatch` 不可反序列化或克隆，持有当前读取/编辑租约；从数据库读取的 PublicationPlan 仅用于恢复展示，不能恢复执行权。再次派发拒绝。Host 重开后 dispatching 进入 unknown，旧 token/授权不复活；未决操作使同资源的新编辑保持隔离。元数据查询按已认证 owner 过滤，不读取文件内容。

当前保留上限为每个本地 Host 的物理资源 64 份计划及 64 MiB 估算量，包含源/结果内容和双方安全属性的保守余量。这是准入限制，不是磁盘 block quota；不代表多个 Host 的全局配额。历史完成记录也继续占用，后续只有在真实备份保留/人工恢复/明确释放流程完成后才可实现有证据的容量释放，不能先删除未知记录解除限额。

实际 SQLite/临时文件测试覆盖：重开保留、owner 隔离、未知不重派、数据库失败全回滚、源修改/撤权拒绝、计划不可改删、数量和字节两个限额。容量测试明确使用合成的终态操作记录，仅证明保留计划计数，不证明文件已经发布。测试先后暴露了未决资源隔离及 invocation/call 唯一约束，均调整测试夹具保持保护规则，没有放宽生产约束。

## 后续实现要求

1. 对当前 fd/源内容/安全属性/父目录身份重新验证，写入并 fsync 自有暂存文件；保留计划必须在效果之前存在。
2. 所有命名空间操作使用 no-replace；捕获旧文件后确认实际版本，冲突和不确定结果保留全部版本，不进行覆盖回滚或未知对象删除。
3. 每个不可逆效果前后保存独立阶段证据，针对阶段间崩溃测试。不能将预览 hash 检查和普通 rename 声称为全局原子内容 CAS；也不能隐瞒命名空间暂时缺口。
4. 成功后仍需完整验证内容、权限、原文件保留及目录持久化，再保存结果；旧 fd 后续写入必须能够被发现或保留其版本。
5. 实现批准编辑的来源版本转换，恢复时保留撤权/删除校验；禁止为了允许编辑而关闭已有来源保护。
6. 完成以上工作和故障测试后才接入普通 Agent/CLI/Desktop，独立编辑同意不得从只读或新建权限推导。
